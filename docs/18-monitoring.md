# 18. Мониторинг и журналы

## Цели и предварительные требования

Объяснять работу компонентов темы «Мониторинг и журналы» и проверять их состояние на практике.

Понадобится Учебная ВМ с systemd.

## Как это работает

Флаги ограничивают текущую загрузку, уровни от warning до emerg и число записей. Метрики показывают динамику, события дают контекст изменения состояния.

Для счётчиков используйте скорость изменения с учётом сброса при перезапуске. Для квантили задержки агрегируйте распределения с одинаковыми границами корзин. При расследовании сохраняйте единый интервал UTC, версии и исходные запросы к метрикам.

## Синтаксис и практический пример

```bash
journalctl -b -p warning -n 10 --no-pager
```

Ожидаемый результат для примера. Появится не более десяти записей в доступном журнале либо сообщение об их отсутствии.

## Справочные примеры

> Команды ниже предназначены для учебной среды. Операции с `sudo`, разделами, сетью, системными службами и учётными записями выполняйте только в одноразовой ВМ с доступом к её консоли.

### Системные журналы

Журналы используются для диагностики ошибок, мониторинга событий и расследования инцидентов.

#### Journalctl

```bash
journalctl
journalctl -xe
journalctl -f
journalctl -b
journalctl -b -1
```

Журналы определённой службы:

```bash
journalctl -u nginx
journalctl -u ssh
```

Фильтрация по времени:

```bash
journalctl --since today
journalctl --since "1 hour ago"
```

Фильтрация ошибок:

```bash
journalctl -p err
```

#### Основные файлы журналов

| Файл | Назначение |
|---|---|
| `/var/log/syslog` | Системные события |
| `/var/log/auth.log` | Аутентификация |
| `/var/log/kern.log` | События ядра |
| `/var/log/nginx/access.log` | HTTP-запросы |
| `/var/log/nginx/error.log` | Ошибки Nginx |
| `/var/log/dpkg.log` | Управление пакетами Debian |

Наличие файлов зависит от дистрибутива и конфигурации журналирования.

#### Размер журналов

```bash
journalctl --disk-usage
```

#### Logrotate

```bash
cat /etc/logrotate.conf
ls /etc/logrotate.d/
```

Проверка конфигурации без внесения изменений:

```bash
sudo logrotate -d /etc/logrotate.conf
```

### Мониторинг системы

#### Информация о системе

```bash
uname -a
cat /etc/os-release
hostnamectl
uptime
```

#### Процессор

```bash
lscpu
nproc
top
```

#### Оперативная память

```bash
free -h
cat /proc/meminfo
vmstat 1
```

#### Диски

```bash
df -h
lsblk
iostat -xz 1
```

#### Сетевые подключения

```bash
ss -s
ip -s link
```

#### Аппаратное обеспечение

```bash
lspci
lsusb
sudo lshw -short
```

#### Инструменты мониторинга

| Инструмент | Назначение |
|---|---|
| htop | Мониторинг процессов |
| btop | Мониторинг ресурсов |
| iotop | Дисковые операции |
| iftop | Сетевой трафик |
| Netdata | Мониторинг в реальном времени |
| Prometheus | Сбор метрик |
| Grafana | Визуализация метрик |
| Zabbix | Мониторинг инфраструктуры |
| smartctl | Диагностика накопителей |

Некоторые инструменты необходимо устанавливать отдельно.

## Применение и диагностика

Проверьте права чтения, наличие постоянного хранилища и единый часовой пояс. Ограничивайте чувствительные поля при экспорте.

## Практика и самопроверка

1. Сопоставьте недавнее изменение конфигурации с журналом соответствующей службы.
2. Почему алерт о росте задержки лучше связывать с насыщением очереди?

# 34. Наблюдаемость с eBPF

## Цели и предварительные требования

Объяснять работу компонентов темы «Наблюдаемость с eBPF» и проверять их состояние на практике.

Понадобится Учебная ВМ Linux и [предыдущая глава](33-namespaces-and-cgroups.md).

## Как это работает

BTF описывает типы ядра, verifier проверяет свойства программ перед загрузкой. Карты передают агрегаты в пользовательское пространство, точки подключения выбираются по задаче.

При загрузке eBPF проверяющий анализирует доступы к памяти и завершение. BTF и CO-RE упрощают перенос наблюдателя между сборками ядра. Для агрегатов удобно обновлять счётчики в карте и считывать их интервально. Сначала проверьте события, допустимые полномочия и влияние сбора.

## Синтаксис и практический пример

```bash
test -r /sys/kernel/btf/vmlinux && printf 'BTF available\n'
```

Ожидаемый результат для примера. При доступном файле печатается BTF available, иначе первая команда возвращает ненулевой статус.

## Применение и диагностика

Проверяйте конфигурацию ядра, возможности bpftool и тип точки подключения. Ограничивайте окно наблюдения и объём собираемых данных.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `bpftool btf dump file /sys/kernel/btf/vmlinux format raw` | Показывает типы от загруженного ядра. Отсутствие файла требует проверки сборки ядра. |
| `bpftool feature probe unprivileged` | Показывает доступные непривилегированному клиенту возможности. Их недостаточно для оценки всех доступных привилегированному процессу событий. |
| Точки и карты | Системные tracepoints лучше соответствуют запросам по событиям. Для счётчиков выбирайте агрегацию и заранее ограничивайте срок наблюдения. |

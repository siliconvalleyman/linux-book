# 07. Пользователи и группы

## Цели и предварительные требования

Проверять членство в группах и различать локальные и сетевые учётные записи.

Понадобится ВМ Debian или Ubuntu.

## Как это работает

Ядро оперирует UID и GID. NSS связывает числовые идентификаторы с именами из локальных или сетевых источников. Дополнительные группы назначаются при запуске сеанса и уже запущенные процессы их не обновляют.

Блокировка пароля через passwd -l ограничивает вход паролем, при этом публичные ключи и действующие токены обрабатываются отдельно. При отзыве доступа выясните, какие механизмы использует служба и какие процессы запускает пользователь. В сетевом каталоге учитывайте срок жизни кэша.

## Синтаксис и практический пример

```bash
getent passwd "$(id -un)"
```

База passwd ищет запись через NSS, id -un получает имя эффективного пользователя.

Ожидаемый результат для примера. Обычно выводятся семь полей через двоеточие, включая UID, GID, домашний каталог и оболочку.

## Справочные примеры

> Команды ниже предназначены для учебной среды. Операции с `sudo`, разделами, сетью, системными службами и учётными записями выполняйте только в одноразовой ВМ с доступом к её консоли.

### Пользователи и группы

> **Внимание.** Изменения из этого раздела выполняйте только в одноразовой ВМ со снимком.

Linux является многопользовательской операционной системой.

#### Типы пользователей

- Root — суперпользователь.
- System User — системная учётная запись.
- Regular User — обычный пользователь.

#### Просмотр информации

```bash
whoami
id
who
w
groups
last
```

#### Создание пользователя

В Ubuntu и Debian:

```bash
sudo adduser developer
```

Низкоуровневый вариант для систем с shadow-utils:

```bash
sudo useradd -m -s /bin/bash developer
sudo passwd developer
```

#### Изменение пароля

```bash
passwd
sudo passwd developer
```

#### Добавление в группу

Ubuntu и Debian:

```bash
sudo usermod -aG sudo developer
```

Fedora и RHEL:

```bash
sudo usermod -aG wheel developer
```

#### Управление группами

```bash
sudo groupadd developers
sudo usermod -aG developers developer
getent group developers
```

#### Переключение пользователя

```bash
su - developer
sudo -i
```

#### Удаление пользователя

```bash
sudo userdel developer
```

Удаление вместе с домашним каталогом:

```bash
# Run only for the disposable account in the lab VM.
sudo userdel -r developer
```

> Перед удалением пользователя убедитесь, что его данные сохранены.

#### Системные файлы

| Файл | Назначение |
|---|---|
| `/etc/passwd` | Информация о пользователях |
| `/etc/shadow` | Хеши паролей и параметры их действия |
| `/etc/group` | Информация о группах |
| `/etc/sudoers` | Правила использования sudo |

Редактирование правил sudo:

```bash
sudo visudo
```

## Применение и диагностика

После изменения групп сравните id в старом и новом сеансе. При использовании LDAP проверьте NSS и кэш.

Меняйте sudoers через visudo. Перед удалением пользователя определите владельцев данных и выполните проверку восстановления.

## Практика и самопроверка

1. Сравните id, groups и getent passwd для своей учётной записи.
2. Почему изменение /etc/group не меняет группы работающего процесса?

# 26. LVM и RAID

## Цели и предварительные требования

Объяснять работу компонентов темы «LVM и RAID» и проверять их состояние на практике.

Понадобится Учебная ВМ Linux и [предыдущая глава](25-selinux-and-apparmor.md).

## Как это работает

LVM собирает PV в VG и выделяет логические тома LV. RAID 1 зеркалирует данные, RAID 0 распределяет блоки без избыточности. Снапшот зависит от оригинального хранилища.

LVM управляет выделением extents из группы, RAID отвечает за схему записи блоков на устройства. Thin provisioning откладывает физическое выделение, поэтому наблюдайте и за данными, и за метаданными. При деградации зеркала не вынимайте накопитель до проверки точной идентификации и наличия копии.

## Синтаксис и практический пример

```bash
lsblk -o NAME,TYPE,SIZE,MOUNTPOINTS
```

Ожидаемый результат для примера. В ВМ с LVM TYPE lvm появляется у логического тома. У программного зеркала возможен тип raid1.

## Применение и диагностика

При деградации сначала найдите устройство по серийному номеру и сверяйте данные pvs, lvs и /proc/mdstat. Не меняйте разделы хоста.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `pvs -o pv_name,vg_name,pv_free` | Единицы физического слоя и свободное место PV. Сверьте точный путь до изменения любой группы. |
| `lvs -a -o lv_name,vg_name,data_percent,metadata_percent` | У thin pool отдельно растут данные и метаданные. Высокий процент в любом из полей требует оценки запаса VG. |
| `mdadm --detail /dev/md/lab` | Показывает состояние компонент программного массива. Для учебного зеркала сравните число активных устройств с `cat /proc/mdstat`. |

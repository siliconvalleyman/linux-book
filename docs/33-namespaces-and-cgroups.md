# 33. Пространства имён и cgroups

## Цели и предварительные требования

Объяснять работу компонентов темы «Пространства имён и cgroups» и проверять их состояние на практике.

Понадобится Учебная ВМ Linux и [предыдущая глава](32-performance-tuning.md).

## Как это работает

Namespace определяет видимость объектов, а cgroup — учёт и лимиты ресурсов. В cgroup v2 единая иерархия организует контроллеры и делегирование.

Mount и PID namespaces задают независимый обзор объектов. Контроллеры cgroup v2 агрегируют нагрузку по иерархии. memory.high включает давление reclaim, memory.max может привести к OOM в группе. На системе с systemd делегируйте поддерево штатным способом и избегайте ручной записи в чужие cgroups.

## Синтаксис и практический пример

```bash
cat /proc/self/cgroup
```

Ожидаемый результат для примера. Запись v2 имеет вид 0::/путь. Контейнер может видеть путь / из-за собственного cgroup namespace.

## Применение и диагностика

Проверьте тип монтирования через findmnt и делегирование systemd. Для объяснения OOM изучите memory.events.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `lsns -t pid` | Показывает PID namespaces, видимые текущей учётной записи. Сопоставьте inode с `readlink /proc/PID/ns/pid`. |
| `findmnt -t cgroup2` | Определяет место монтирования v2, а `/proc/PID/cgroup` даёт относительный путь группы. |
| `memory.current` и `memory.events` | Первый файл отражает текущее потребление, второй содержит накопленные события `high`, `max` и `oom_kill`. Сравнивайте разности событий за период. |

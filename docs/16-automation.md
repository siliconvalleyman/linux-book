# 16. Автоматизация по расписанию

## Цели и предварительные требования

Объяснять работу компонентов темы «Автоматизация по расписанию» и проверять их состояние на практике.

Понадобится Учебная ВМ с systemd.

## Как это работает

calendar разбирает выражение OnCalendar и показывает следующее срабатывание. Persistent может компенсировать пропущенный календарный запуск. Cron обычно запускает задания с урезанным окружением.

Таймер пары service и timer позволяет отдельно диагностировать план и результат выполнения. Календарные выражения привязаны ко времени, монотонные OnBootSec и OnUnitActiveSec — к относительным интервалам. Для Cron задайте PATH и защиту от наложения запусков, если задача работает дольше своего периода.

## Синтаксис и практический пример

```bash
systemd-analyze calendar 'Mon *-*-* 09:00:00'
```

Ожидаемый результат для примера. В выводе ожидается строка Next elapse с ближайшим понедельником.

## Справочные примеры

> Команды ниже предназначены для учебной среды. Операции с `sudo`, разделами, сетью, системными службами и учётными записями выполняйте только в одноразовой ВМ с доступом к её консоли.

### Автоматизация задач

#### Cron

Просмотр задач:

```bash
crontab -l
```

Редактирование:

```bash
crontab -e
```

Формат:

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week
│ │ │ └──── Month
│ │ └────── Day of month
│ └──────── Hour
└────────── Minute
```

#### Примеры

Каждый день в 02:00:

```cron
0 2 * * * /home/user/backup.sh
```

Каждые 15 минут:

```cron
*/15 * * * * /home/user/check.sh
```

Каждый понедельник:

```cron
0 9 * * 1 /home/user/report.sh
```

При запуске системы:

```cron
@reboot /home/user/start.sh
```

#### Systemd Timers

Файл `backup.timer`:

```ini
[Unit]
Description=Daily Backup Timer

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

Для работы таймера необходим соответствующий файл `backup.service`, определяющий выполняемую задачу.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer
systemctl list-timers
```

## Применение и диагностика

При пропуске запуска проверьте часовой пояс, активность таймера и результат соответствующего сервиса. Продумайте недопущение параллельных запусков.

## Практика и самопроверка

1. Сравните календарные правила daily и Mon *-*-* 09:00:00.
2. Что произойдёт, если предыдущий экземпляр cron-задачи ещё работает?

# 29. Конфигурация с Ansible

## Цели и предварительные требования

Объяснять работу компонентов темы «Конфигурация с Ansible» и проверять их состояние на практике.

Понадобится Ansible и Python в учебной ВМ.

## Как это работает

Запятая выбирает inline inventory, -c local выполняет модуль локально. Модуль ping проверяет выполнение Python на целевом узле. Идемпотентный модуль меняет только расходящееся состояние.

Inventory описывает цели, а play сопоставляет их с задачами. Используйте встроенные модули для ожидаемых свойств файлов и служб. Командный модуль требует явного условия идемпотентности. Перед применением к группе проверьте список хостов, diff и отдельный стенд.

## Синтаксис и практический пример

```bash
ansible localhost -i localhost, -c local -m ansible.builtin.ping
```

Ожидаемый результат для примера. Ожидается SUCCESS, changed false и ping pong.

## Применение и диагностика

При UNREACHABLE проверьте inventory и SSH; при ошибке интерпретатора — ansible_python_interpreter. Применяйте Vault для зашифрованных данных.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `ansible-inventory -i inventory --graph` | Выводит группы и узлы. Сверяйте порядок источников inventory, если хост попал в неожиданную группу. |
| `ansible-playbook -i inventory site.yml --list-hosts` | Показывает выбранные хосты для play без применения задач. |
| `ansible-playbook -i inventory site.yml --check --limit lab` | Ограничивает выполнение узлами lab и просит симуляцию. Это зависит от поддержки модулей. Не включайте diff для задач с секретами. |

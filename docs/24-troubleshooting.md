# 24. Методика диагностики

## Цели и предварительные требования

Объяснять работу компонентов темы «Методика диагностики» и проверять их состояние на практике.

Понадобится Учебная ВМ со strace.

## Как это работает

Флаг -e ограничивает классы вызовов, -o направляет трассу в файл. Код errno связывает симптом приложения с конкретным отказом ОС.

Ограничьте диагноз до воспроизводимого запроса и зафиксируйте время. Сначала снимите состояние маршрутов, процессов, места и журнала, затем меняйте одну переменную. Для неизвестных бинарников проверяйте зависимости readelf, чтобы не инициировать выполнение при анализе.

## Синтаксис и практический пример

```bash
strace -e trace=openat -o trace.log cat /etc/os-release
```

Ожидаемый результат для примера. Одна из строк журнала содержит openat для /etc/os-release и дескриптор либо ошибку.

## Справочные примеры

> Команды ниже предназначены для учебной среды. Операции с `sudo`, разделами, сетью, системными службами и учётными записями выполняйте только в одноразовой ВМ с доступом к её консоли.

### Диагностика и устранение ошибок

#### Permission denied

Проверка пользователя и разрешений:

```bash
whoami
id
ls -la
namei -l /path/to/file
```

Исправляйте только необходимые права доступа.

#### Command not found

```bash
command -v command_name
echo "$PATH"
```

Проверьте, установлен ли необходимый пакет.

#### No space left on device

```bash
df -h
df -i
du -h --max-depth=1 /var
```

Проблема может быть связана как с заполнением диска, так и с исчерпанием inode.

#### Address already in use

```bash
sudo ss -tulpn
sudo lsof -i :8080
```

Определите процесс, занимающий порт, прежде чем останавливать его.

#### Служба не запускается

```bash
systemctl status service-name
journalctl -u service-name -n 100
systemctl --failed
```

#### Проблемы с сетью

```bash
ip addr
ip route
ping -c 4 8.8.8.8
getent hosts example.com
curl -I https://example.com
```

#### Высокая нагрузка на процессор

```bash
uptime
top
ps aux --sort=-%cpu | head
```

#### Нехватка оперативной памяти

```bash
free -h
ps aux --sort=-%mem | head
sudo journalctl -k | grep -i "out of memory"
```

#### Диагностика системных вызовов

```bash
strace -o trace.log command
```

#### Проверка библиотек

```bash
ldd /usr/bin/bash
```

Не используйте `ldd` для неизвестных и недоверенных исполняемых файлов.

#### Универсальный алгоритм диагностики

1. Определить симптомы проблемы.
2. Проверить последние изменения.
3. Изучить системные журналы.
4. Проверить ресурсы системы.
5. Проверить конфигурацию.
6. Найти первопричину.
7. Внести минимальные изменения.
8. Проверить результат.
9. Задокументировать решение.

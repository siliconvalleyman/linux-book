# 30. Инфраструктура с Terraform

## Цели и предварительные требования

Объяснять работу компонентов темы «Инфраструктура с Terraform» и проверять их состояние на практике.

Понадобится Terraform CLI и отдельный рабочий каталог.

## Как это работает

fmt канонизирует оформление HCL; -check возвращает ненулевой статус при отличиях. План строится из конфигурации, state и данных провайдера; state связывает адрес ресурса с внешним идентификатором.

Ресурс связывается со state по адресу конфигурации. Смена имени может выглядеть как удаление и создание, пока не указано перемещение. Для команды разделяйте окружения и права на backend, используйте блокировки и рассматривайте сохранённый план как чувствительный артефакт.

## Синтаксис и практический пример

```bash
terraform fmt -check -diff
```

Ожидаемый результат для примера. Для оформленных файлов вывод пустой, статус 0.

## Применение и диагностика

Проверяйте блокировку state и любые планы с replace. Вывод plan и state может содержать секреты, поэтому ограничивайте доступ.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `terraform validate` | Проверяет согласованность конфигурации после инициализации. Доступность удалённого API проверяется при планировании. |
| `terraform plan -out=review.tfplan` | Сохраняет конкретный план для анализа. Защищайте файл теми же правами, что и state. |
| `terraform show -no-color review.tfplan` | Показывает изменения. Если предлагается замена ресурса, проверьте зависимость, время простоя и допустимость потери данных. |

## Практика и самопроверка

# 32. Анализ производительности

## Цели и предварительные требования

Объяснять работу компонентов темы «Анализ производительности» и проверять их состояние на практике.

Понадобится Учебная ВМ Linux и [предыдущая глава](31-cicd.md).

## Как это работает

PSI измеряет время задержек из-за конкуренции за ресурс. some означает наличие остановленных задач, full — одновременную остановку всех непростаивающих задач в наблюдаемой области.

Начинайте с симптома пользователя и количественной цели. Снимайте baseline при одинаковой нагрузке, сравнивайте устойчивые интервалы и изменяйте по одному параметру. Для CPU смотрите runnable queue и throttling, для I/O — задержку и глубину очереди, для памяти — PSI и reclaim.

## Синтаксис и практический пример

```bash
cat /proc/pressure/io
```

Ожидаемый результат для примера. При наличии PSI появляются some и full с avg10, avg60, avg300 и total.

## Применение и диагностика

Сравнивайте PSI, аппаратные метрики и задержку запроса в одном интервале. Изменяйте по одной настройке, сохраняя исходные параметры.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `vmstat 1 5` | Снимки очередей и памяти. При сопоставлении интервалов учитывайте, что ряд полей первой строки усреднён с момента загрузки. |
| `iostat -y -xz 1 5` | Дисковая задержка и нагрузка. Высокий `%util` для параллельного устройства интерпретируют вместе с очередью и временем ответа. |
| `pidstat -u -r -d 1 5` | Соотносит нагрузку с процессами. Узкий интервал и стабильный профиль запросов повышают сопоставимость замеров. |

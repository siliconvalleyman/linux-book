# 27. Виртуализация и KVM

## Цели и предварительные требования

Объяснять работу компонентов темы «Виртуализация и KVM» и проверять их состояние на практике.

Понадобится Linux с установленными QEMU, KVM, libvirt и virsh.

## Как это работает

KVM предоставляет аппаратную виртуализацию; QEMU моделирует устройства, libvirt управляет жизненным циклом. Системный и пользовательский URI имеют разные наборы ВМ.

Полная виртуализация предоставляет гостю виртуальные CPU, память и устройства. Virtio уменьшает накладные расходы за счёт специализированного интерфейса между гостем и хостом. Снимок диска работающей ВМ может быть только crash-consistent: для баз данных согласуйте момент создания с приложением или штатным backup API.

## Синтаксис и практический пример

```bash
virsh -c qemu:///system list --all
```

Ожидаемый результат для примера. Выводится таблица известных доменов, в том числе выключенных. Без доступа к системному сокету будет ошибка.

## Применение и диагностика

При проблемах проверьте /dev/kvm, права и доступность вложенной виртуализации. Изолируйте сеть новых ВМ.

### Что проверять в рабочей среде

| Команда или этап | Что даёт проверка |
| --- | --- |
| `virsh dominfo ИМЯ` | Проверяет состояние гостя и его выделенные ресурсы. Параметры виртуальных устройств смотрите в `virsh dumpxml`. |
| `virsh domiflist ИМЯ` | Перечисляет интерфейсы ВМ и их источник. При отсутствии сети проверьте подключение к нужной виртуальной сети и адрес внутри гостя. |
| `virsh domblklist ИМЯ --details` | Связывает виртуальный диск с файлом или устройством хоста. Перед восстановлением проверьте полную цепочку образов. |

# Корневая ФС только для чтения

| Уровень | Время |
| --- | --- |
| Продвинутый | 15 мин |

## Цель и подготовка

Проверьте невозможность записи в корень и возможность записи в выделенный tmpfs.

Понадобится Docker с busybox:stable. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. В корне возникает Read-only file system, итоговый статус 0. Сначала проверьте вывод, затем запустите проверку ниже.
3. Проверьте, что тест выполняется в контейнере, а не в оболочке хоста.

## Полное решение

```bash
docker run --rm --read-only --tmpfs /tmp:rw,nosuid,nodev busybox:stable sh -c 'if touch /outside; then exit 1; fi; touch /tmp/inside; test -f /tmp/inside'
```

## Проверка

```bash
docker run --rm --read-only busybox:stable sh -c 'if touch /probe; then exit 1; fi'
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

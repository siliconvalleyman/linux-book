# Ограничения контейнера

| Уровень | Время |
| --- | --- |
| Продвинутый | 15 мин |

## Цель и подготовка

Запустите свой контейнер с ограничением памяти и PID и прочитайте параметры.

Понадобится Учебный Docker с busybox:stable. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. Значения 67108864 и 32. Сначала проверьте вывод, затем запустите проверку ниже.
3. Если настройки отклонены, проверьте доступность контроллеров на демоне.

## Полное решение

```bash
container=$(docker run -d --memory 64m --pids-limit 32 busybox:stable sleep 120)
docker inspect --format '{{.HostConfig.Memory}} {{.HostConfig.PidsLimit}}' "$container"
```

## Проверка

```bash
test "$(docker inspect --format '{{.HostConfig.Memory}} {{.HostConfig.PidsLimit}}' "$container")" = '67108864 32'
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
docker rm -f "$container"
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

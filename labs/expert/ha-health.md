# Подтверждение жизнеспособности резервного узла

| Уровень | Время |
| --- | --- |
| Экспертный | 20 мин |

## Цель и подготовка

Сымитируйте выбор обслуживающего узла при недоступном первом адресе.

Понадобится Python 3, curl, два свободных loopback-порта. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. Выбран резервный узел secondary. Сначала проверьте вывод, затем запустите проверку ниже.
3. Убедитесь, что 18101 не занят, а 18102 слушает процесс лаборатории.

## Полное решение

```bash
printf 'secondary\n' > index.html; python3 -m http.server 18102 --bind 127.0.0.1 > http.log 2>&1 & server=$!
sleep 1
if ! curl --max-time 2 -fsS http://127.0.0.1:18101/ > result
then curl --max-time 2 -fsS http://127.0.0.1:18102/ > result; fi
```

## Проверка

```bash
grep -Fx secondary result
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
kill "$server" 2>/dev/null || true; wait "$server" 2>/dev/null || true
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

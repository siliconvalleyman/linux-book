# Подсчёт событий tracepoint в ВМ

| Уровень | Время |
| --- | --- |
| Экспертный | 25 мин |

## Цель и подготовка

Подключите краткое наблюдение к системному событию и агрегируйте только счётчик.

Понадобится Одноразовая ВМ, sudo, bpftrace и tracepoint sys_enter_getpid. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. При работе трассировщика появляется счётчик calls. Сначала проверьте вывод, затем запустите проверку ниже.
3. Проверьте наличие tracepoint и доступность tracefs. Не собирайте аргументы вызовов.

## Полное решение

```bash
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_getpid { @calls = count(); } interval:s:3 { exit(); }' > bpf.txt & tracer=$!
sleep 1
for i in {1..10}
do python3 -c 'import os; os.getpid()'; done
wait "$tracer"
```

## Проверка

```bash
grep -E '@calls: [1-9][0-9]*' bpf.txt
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

# Изоляция имён Kubernetes

| Уровень | Время |
| --- | --- |
| Экспертный | 18 мин |

## Цель и подготовка

Создайте отдельное пространство и проверьте, что оно активно.

Понадобится Локальный учебный кластер kubectl и права на namespace. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. Namespace переходит в Active. Сначала проверьте вывод, затем запустите проверку ниже.
3. Остановитесь, если контекст не указывает на локальный стенд.

## Полное решение

```bash
kubectl config current-context
namespace="handbook-$BASHPID"
kubectl create namespace "$namespace"
```

## Проверка

```bash
test "$(kubectl get ns "$namespace" -o jsonpath='{.status.phase}')" = Active
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
kubectl delete namespace "$namespace" --wait=false
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

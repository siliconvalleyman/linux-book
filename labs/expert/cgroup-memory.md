# Лимит памяти transient unit

| Уровень | Время |
| --- | --- |
| Экспертный | 20 мин |

## Цель и подготовка

Задайте MemoryMax и прочитайте memory.max из нужной группы.

Понадобится ВМ systemd с cgroup v2 и sudo. Выполняйте команды только в одноразовой учебной ВМ. Перед изменениями кластера или Docker подтвердите, что работаете с локальным стендом.

Откройте Bash и подготовьте рабочий каталог.

```bash
previous_directory=$PWD
lab=$(mktemp -d "${TMPDIR:-/tmp}/handbook.XXXXXXXX")
cd -- "$lab"
```

## Ход работы

1. Выполните описанное действие в подготовленном каталоге. Используйте команды из решения, если нужно сверить последовательность.
2. Значение 67108864 байт. Сначала проверьте вывод, затем запустите проверку ниже.
3. Значение max указывает, что лимит не применился на данном уровне.

## Полное решение

```bash
sudo systemd-run --wait --pipe --collect -p MemoryMax=64M /bin/sh -c 'p=$(cut -d: -f3 /proc/self/cgroup); cat "/sys/fs/cgroup$p/memory.max"' > memory
```

## Проверка

```bash
grep -Fx 67108864 memory
```

Ожидается код 0. Если команда печатает результат, сопоставьте его с ожидаемым состоянием из задания.

## Очистка

Завершите созданные ресурсы и удалите файлы временного каталога. Для упражнений, меняющих состояние системы или кластера, при частичном сбое верните снимок ВМ.

```bash
cd -- "$previous_directory" &&
    [[ ${lab:-} == "${TMPDIR:-/tmp}"/handbook.???????? && -d $lab && ! -L $lab ]] &&
    find "$lab" -xdev -depth -mindepth 1 -delete &&
    rmdir -- "$lab"
```

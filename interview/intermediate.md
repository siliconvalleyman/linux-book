# Сети и эксплуатация Linux

## Вопросы и ответы

### Что измеряет load average?

В Linux это усреднённое число выполняемых или готовых задач и задач в непрерываемом ожидании. Load может расти из-за дисков без загрузки CPU. Сверьте vmstat, PSI и задержку приложения.

### Почему доступная память важнее свободной?

Ядро использует память для кэша, часть которого освобождается под нагрузкой. MemAvailable оценивает доступность памяти для приложений. Для диагноза добавьте PSI, swap и события групп памяти.

### Что означает состояние D у процесса?

Поток находится в непрерываемом сне, часто при ожидании I/O. SIGKILL может остаться ожидающим до выхода из этого состояния. Изучают метрики устройства, syscalls и журналы ядра.

### Почему после удаления файла df не меняется?

Блоки освобождаются, когда исчезнет последняя ссылка и открытая ссылка процесса. lsof +L1 помогает найти удерживающий процесс. Службе может понадобиться корректное переоткрытие журнала.

### Зачем применять readiness и liveness отдельно?

Readiness исключает неподготовленный экземпляр из маршрутизации, не убивая его. Liveness запускает перезапуск зависшего процесса. Объединение сигналов может превратить временную недоступность зависимости в цикл перезапусков.

### Как проверить, что DNS не причина отказа HTTP?

Сопоставьте ответ системного резолвера со значимым DNS-ответом и проверьте подключение к известному адресу с правильными Host и SNI. Для curl это можно сделать через --resolve на своём стенде.

### Почему nginx возвращает 502?

Обычно прокси не смог получить корректный ответ upstream. Сопоставьте ошибку с отказом TCP, TLS или закрытием соединения. Проверьте адрес backend из той же сетевой среды, где работает Nginx.

### Что означает 504 в прокси?

В пределах таймаута upstream не предоставил нужный ответ. Проверьте здоровье backend, время соединения и чтения, очереди и запросы. Повышение таймаута может временно скрыть насыщение.

### Чему доверяет клиент SSH при первом соединении?

Открытому ключу хоста, отпечаток которого подтверждён по доверенному каналу. Сохранённый known_hosts защищает последующие подключения. При смене ключа подтвердите её через консоль или администратора.

### Как проверить sshd_config для конкретного клиента?

sshd -t проверяет структуру, sshd -T -C вычисляет итоговую конфигурацию с учётом Match. Перед reload сохраните текущий сеанс и откройте параллельный тестовый вход.

### Почему служба запускается вручную, но не через systemd?

Отличаются пользователь, рабочий каталог, окружение, видимость временных путей и ограничения юнита. Сверьте systemctl show, systemctl cat и journalctl -u, затем воспроизведите с похожим окружением.

### Как отменить неудачное изменение fstab?

В консоли ВМ восстановите предыдущую копию, затем сравните UUID с lsblk и выполните findmnt --verify. Подтвердите монтирование конкретной точки перед новой загрузкой. Для некритичных томов оцените nofail.

### Чем задержка диска отличается от throughput?

Throughput отражает объём передачи, latency — время операции. Устройство может выдавать высокую скорость при большой очереди и высокой задержке. Смотрите размер запроса, время ожидания и наблюдаемый профиль нагрузки.

### Почему crontab не видит команду из интерактивной оболочки?

Cron запускает задания в контролируемом окружении и обычно не читает интерактивные стартовые файлы Bash. Задайте PATH, рабочий каталог и абсолютные пути для задач, которым это необходимо.

### Что даёт синхронное монтирование журнала приложения?

Для гарантии записи учитывайте буферизацию приложения, ФС и накопителя. fsync файла и детали публикации записи каталога важны при сбое питания. Для приложений используйте поддерживаемые механизмы долговечности.

### Что проверить при конфликте TCP-порта?

Найдите слушателя через ss, уточните адрес привязки, namespace и владельца процесса. Проверьте, не зарезервирован ли порт systemd-сокетом или контейнерным пробросом. Меняйте конфигурацию с учётом зависимых клиентов.

### Для чего нужны записи PTR?

PTR связывает адрес с доменным именем при обратном DNS-запросе. Обратная зона обслуживается владельцем адресного диапазона. PTR сам по себе не подтверждает владение именем из прямой зоны.

### Как проверить корректность ротации журнала?

Выполните logrotate -d, проверьте владельца новых файлов и поведение процесса при переоткрытии. copytruncate допускает окно потери записей. Предпочтителен штатный сигнал или механизм логирования приложения.

### Что означает код 100 у dnf check-update?

Доступны обновления. Ноль означает отсутствие пакетов для обновления, остальные коды требуют интерпретации согласно справке. Пайплайн должен обрабатывать 100 как ожидаемый результат.

### Почему systemd enable не гарантирует активную службу?

Enable устанавливает ссылки для будущих транзакций загрузки. Активность отражает состояние текущего менеджера. Для обоих действий применяется enable --now, после чего проверяют состояние и журнал.

## Практические сценарии

### Как решить задачу «Итоговый профиль SSH» на стенде?

Напишите отдельный клиентский профиль и проверьте его без соединения. Записаны имя оператора, адрес и порт. Проверьте имя псевдонима Host и параметр -F.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -Fx 'port 2222' effective
```

[Условия, команды и разбор задачи](../labs/intermediate/ssh-profile.md)

### Как решить задачу «Отпечаток ключа» на стенде?

Создайте учебную пару ключей с парольной фразой и прочитайте отпечаток публичной части. Отпечаток начинается с SHA256:, тип ED25519. Аргумент -f задаёт отдельное имя, чтобы не перезаписать пользовательский ключ.

Критерий приёмки проверяется в подготовленном стенде.

```bash
ssh-keygen -lf lab_id.pub | grep -F '(ED25519)'
```

[Условия, команды и разбор задачи](../labs/intermediate/ssh-key.md)

### Как решить задачу «Проверка сервера SSH» на стенде?

Проверьте штатный конфиг и итоговые способы входа, не меняя сервер. При корректном конфиге тест не печатает ошибок. Если нет /run/sshd, запустите штатную службу учебной ВМ.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -E '^(pubkeyauthentication|passwordauthentication) (yes|no)$' effective
```

[Условия, команды и разбор задачи](../labs/intermediate/ssh-config-test.md)

### Как решить задачу «Маршрут loopback» на стенде?

Проверьте IPv4-маршрут к loopback. В выводе появляется dev lo. В нестандартном namespace проверьте состояние интерфейса.

Критерий приёмки проверяется в подготовленном стенде.

```bash
ip -4 route get 127.0.0.1 | grep -F 'dev lo'
```

[Условия, команды и разбор задачи](../labs/intermediate/loopback-route.md)

### Как решить задачу «Проверка локального HTTP» на стенде?

Запустите HTTP для своего каталога и проверьте статус и тело. В ответе ready. Если порт занят, сопоставьте процесс и адрес через ss.

Критерий приёмки проверяется в подготовленном стенде.

```bash
cmp index.html response
```

[Условия, команды и разбор задачи](../labs/intermediate/http-probe.md)

### Как решить задачу «Сокет слушателя» на стенде?

Найдите локальный слушатель и проверьте адрес привязки. В выводе присутствует 127.0.0.1:18081. Если слушателя нет, изучите http.log.

Критерий приёмки проверяется в подготовленном стенде.

```bash
ss -H -ltn 'sport = :18081' | grep -F 127.0.0.1:18081
```

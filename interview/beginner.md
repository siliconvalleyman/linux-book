# Основы Linux и Bash

## Вопросы и ответы

### Что именно называют ядром Linux?

Ядро реализует системные вызовы, планирование, память, драйверы и сетевой стек. Дистрибутив добавляет библиотеки, оболочки, репозитории и правила обновления. Версию пользовательского окружения смотрят в /etc/os-release, версию загруженного ядра — через uname -r.

### Что произойдёт с относительным путём после cd?

Ядро разрешает относительный путь от рабочего каталога процесса. Новый дочерний процесс наследует каталог, абсолютный путь начинается от видимого корня. Для надёжных заданий задайте WorkingDirectory либо абсолютный путь.

### Почему текстовый файл виден, но открыть его нельзя?

Чтение содержимого и поиск имени регулируются раздельно. Нужен x на каждом родительском каталоге, r на файле и разрешение обязательной политики. namei -l помогает найти первый проблемный компонент.

### Зачем указывать двойные кавычки вокруг переменной пути?

Кавычки сохраняют значение единым аргументом, включая пробелы и шаблонные символы. Без них Bash может выполнить field splitting и pathname expansion. Для списка путей используется массив с раскрытием "${files[@]}".

### Что делают > и >> до вызова программы?

Оболочка выполняет перенаправление до запуска команды. > создаёт либо обнуляет файл, >> открывает на дописывание. Поэтому преобразование вида sed ... input > input теряет вход до чтения.

### Чем абсолютный путь отличается от pwd -P?

Абсолютный путь начинается с / и может содержать символические ссылки. pwd -P возвращает путь текущего каталога после разрешения ссылок. Это важно при безопасной проверке дерева перед изменением файлов.

### Чем интерактивная оболочка отличается от login shell?

Интерактивность определяет наличие сеанса команд, а login — режим входа и набор стартовых файлов. Bash может читать .bashrc для интерактивного не-login и .bash_profile или .profile для login. Проверьте фактический режим, прежде чем добавлять настройки.

### Зачем указывать -- перед именем файла?

Многие GNU-команды трактуют аргумент, начинающийся с дефиса, как флаг. -- завершает разбор параметров. Альтернатива для локального пути — префикс ./, но поддержка -- зависит от инструмента.

### Почему wc -l может показать ноль для непустого файла?

Он считает переводы строки, поэтому последний незавершённый фрагмент может не учитываться. Осмотрите файл через od или sed -n l и проверьте, какие записи ожидает следующий потребитель.

### Что означает код 1 у grep?

Совпадений нет. Код 0 означает найденную строку, 2 обычно означает ошибку ввода или шаблона. В скрипте обрабатывайте эти результаты раздельно, особенно с set -e.

### Как каталог получает право наследовать группу?

Бит SGID на каталоге заставляет новые записи наследовать группу каталога. Для совместной записи нужно дополнительно проверить права на каталог и default ACL, потому что одна группа не предоставляет права записи автоматически.

### Почему sudo не поднимает привилегии у перенаправления >?

Файл открывает исходная оболочка до запуска sudo. Для доверенного файла используют инструмент вроде sudo tee с контролируемым вводом. Перед заменой системного конфига нужны резервная копия и проверка синтаксиса.

### Что означает sticky bit на общем каталоге?

Удаление и переименование чужой записи ограничено владельцем файла, владельцем каталога и привилегированными процессами. Это позволяет нескольким пользователям писать в /tmp без взаимного удаления файлов.

### Какие данные lstat получает у символической ссылки?

lstat возвращает свойства самой ссылки, stat обычно следует за ней. Поэтому битая ссылка существует как запись, даже если её цель отсутствует. В Bash это различают test -L и test -e.

### Зачем явно задавать LC_ALL=C при обработке текста?

Локаль влияет на сортировку, классы символов, числа и язык выходных сообщений. C даёт предсказуемое байтовое упорядочивание. Для сортировки привычного пользователю естественного текста применяйте соответствующую локаль.

### Чем id отличается от чтения /etc/group?

id без аргументов показывает текущие идентификаторы процесса, включая унаследованные группы. /etc/group содержит локальные записи и не показывает все данные NSS. После смены членства сравните id в новом сеансе.

### Что происходит в конвейере Bash с кодом завершения?

По умолчанию берётся статус последней команды, а pipefail возвращает статус крайней справа завершившейся неуспешно команды. В PIPESTATUS можно сразу прочитать статусы всех этапов.

### Чем shell builtin отличается от одноимённого файла?

Встроенная команда выполняется внутри оболочки и может изменить её состояние. Внешняя программа запускается отдельно. type -a показывает приоритеты, что важно для cd, printf и команд с переопределениями.

### Как узнать, что APT выберет пакет из нужного репозитория?

apt-cache policy показывает кандидата, источники и приоритеты. Сравните ожидаемый origin и версию, затем моделируйте установку. Присутствие пакета в репозитории само по себе не означает его выбор.

### Почему обратный слеш перед переводом строки полезен?

Неэкранированная пара обратного слеша и перевода строки удаляется Bash до разбиения на аргументы. Это позволяет разбить длинную команду. Пробел после обратного слеша ломает продолжение.

## Практические сценарии

### Как решить задачу «Рабочий каталог» на стенде?

Войдите в созданный каталог и выведите физический путь. Путь заканчивается именем временного каталога. Если путь отличается, проверьте символические ссылки через realpath.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(pwd -P)" = "$(realpath "$lab")"
```

### Как решить задачу «Текущая учётная запись» на стенде?

Получите эффективный UID и найдите запись passwd через NSS. Третье поле записи совпадает с UID. При пустом выводе проверьте NSS.

Критерий приёмки проверяется в подготовленном стенде.


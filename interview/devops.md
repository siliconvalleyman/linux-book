# DevOps, Docker и Kubernetes

## Вопросы и ответы

### Зачем фиксировать образ по digest?

Тег может указывать на другой артефакт со временем. Digest связывает развёртывание с конкретным manifest. Установите процесс регулярного обновления и проверки новых digest.

### Что меняет порядок слоёв Dockerfile?

Кэш повторно используется до первого изменившегося шага. Отделение манифеста зависимостей от исходников ускоряет пересборки. Для безопасности секреты передают через механизмы BuildKit, поскольку удаление файла в последующем слое не удаляет его из старого.

### Когда Compose depends_on недостаточно?

Порядок создания контейнеров не гарантирует готовность приложения. Для Compose используйте healthcheck и условие service_healthy, когда это поддерживается. Клиент всё равно должен повторять подключения после временных отказов.

### Зачем запросы ресурсов Kubernetes указывают отдельно от лимитов?

Scheduler учитывает requests при размещении. Limits задают границы использования, например throttling CPU или завершение при нехватке памяти. Подбирайте значения по наблюдениям и проверяйте влияние на SLO.

### Как отличить ConfigMap от Secret в Kubernetes?

Это разные типы API с разной обработкой и доступом. Кодирование base64 само по себе не шифрует. Используйте минимальный RBAC, шифрование хранения и предпочтительно внешнее управление секретами по требованиям.

### Почему Terraform state нуждается в блокировке?

Два процесса могли бы начать от одного состояния и записать несовместимые изменения. Backend с блокировкой сериализует изменение состояния. Раздавайте права и на блокировку, и на контролируемое восстановление.

### Что делает Terraform plan с изменением вне Terraform?

По умолчанию он читает состояние через провайдер и сопоставляет фактические параметры с декларацией. План может предложить восстановление, импорт или замену. Обязательно проверьте действие replace на критичных ресурсах.

### Зачем Ansible handler вызывают через notify?

Обновление службы можно выполнить после изменения конфигурации и свести повторные уведомления к одному запуску. Сначала проверьте конфигурацию модулями и validate. Учитывайте время выполнения handlers и поведение при сбое.

### Как безопасно раскатывать изменения на несколько узлов?

Выберите ограниченный размер партии, проверьте обратную совместимость, готовность и метрики после каждой. При провале приостановите следующий шаг. Завершение rollout и доступность для клиентов проверяют отдельно.

### Как выбрать артефакт CI для публикации?

Выберите результат конкретного проверенного коммита, сохраните digest и сведения о зависимостях. Доставка должна получать именно этот объект. Повторная сборка на этапе deploy может подтянуть изменившиеся пакеты.

### Зачем нужен PodDisruptionBudget?

Он ограничивает добровольные вытеснения через механизм eviction. Это помогает при обслуживании узлов, но не предотвращает внезапные потери и прямое удаление. Проверьте реплики, разброс по зонам и фактическую политику выселения.

### Как отладить сервис с пустым списком EndpointSlice?

Сверьте namespace, метки Pod и selector Service, затем проверьте готовность и условия endpoints. Если у Service выбран неверный порт, endpoints могут существовать без работающего подключения.

## Практические сценарии

### Как решить задачу «Проверка digest образа» на стенде?

Загрузите busybox и найдите digest для последующей фиксации. В digest присутствует @sha256:. Локально собранный образ может не иметь RepoDigests.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -E '@sha256:[[:xdigit:]]{64}$' digest
```

[Условия, команды и разбор задачи](../labs/advanced/image-digest.md)

### Как решить задачу «Ограничения контейнера» на стенде?

Запустите свой контейнер с ограничением памяти и PID и прочитайте параметры. Значения 67108864 и 32. Если настройки отклонены, проверьте доступность контроллеров на демоне.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(docker inspect --format '{{.HostConfig.Memory}} {{.HostConfig.PidsLimit}}' "$container")" = '67108864 32'
```

[Условия, команды и разбор задачи](../labs/advanced/container-limits.md)

### Как решить задачу «Корневая ФС только для чтения» на стенде?

Проверьте невозможность записи в корень и возможность записи в выделенный tmpfs. В корне возникает Read-only file system, итоговый статус 0. Проверьте, что тест выполняется в контейнере, а не в оболочке хоста.

Критерий приёмки проверяется в подготовленном стенде.

```bash
docker run --rm --read-only busybox:stable sh -c 'test ! -w /'
```

[Условия, команды и разбор задачи](../labs/advanced/container-readonly.md)

### Как решить задачу «Проверка модели Compose» на стенде?

Создайте описание сервиса и проверьте результирующее имя. В списке один сервис worker. Используйте пробелы и проверьте имя файла.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(docker compose config --services)" = worker
```

[Условия, команды и разбор задачи](../labs/advanced/compose-validation.md)

### Как решить задачу «Задание Compose» на стенде?

Запустите одноразовую задачу в отдельном проекте и заберите её код. Файл содержит finished. Если daemon недоступен, проверьте контекст и права.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -Fx finished run.log
```

[Условия, команды и разбор задачи](../labs/advanced/compose-run.md)

### Как решить задачу «Заголовок обратного прокси» на стенде?

Проксируйте запрос между локальными виртуальными серверами; выставьте X-Lab и верните его с upstream. Тело содержит verified. Проверьте слушатели и добавленные заголовки.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(cat actual)" = verified
```

[Условия, команды и разбор задачи](../labs/advanced/proxy-headers.md)

### Как решить задачу «Группы inventory» на стенде?

Опишите один узел с local connection и прочитайте JSON inventory. Под web показан localhost. Проверьте порядок ключей и аргумент -i.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -F 'localhost' graph
```

[Условия, команды и разбор задачи](../labs/advanced/ansible-inventory.md)

### Как решить задачу «Повторный запуск модуля Ansible» на стенде?

Создайте учебный каталог встроенным модулем file и повторите запуск. Второй вызов показывает SUCCESS и changed false. Проверьте, что вывод CLI в обычном, а не минимальном формате.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test -d artifact && grep -E '"changed": false' replay
```

[Условия, команды и разбор задачи](../labs/advanced/ansible-idempotence.md)

### Как решить задачу «Прогноз без записи» на стенде?

Попросите Ansible спрогнозировать создание каталога. План содержит changed true, каталог отсутствует. Проверяйте поддержку check mode у выбранного модуля.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -E '"changed": true' plan && test ! -e future
```

[Условия, команды и разбор задачи](../labs/advanced/ansible-check.md)

### Как решить задачу «Изоляция имён Kubernetes» на стенде?

Создайте отдельное пространство и проверьте, что оно активно. Namespace переходит в Active. Остановитесь, если контекст не указывает на локальный стенд.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(kubectl get ns "$namespace" -o jsonpath='{.status.phase}')" = Active
```

[Условия, команды и разбор задачи](../labs/expert/k8s-namespace.md)

### Как решить задачу «Одноразовое задание Kubernetes» на стенде?

Создайте Job в отдельном пространстве, дождитесь завершения и прочитайте журнал. Job имеет Complete, журнал содержит completed. При ImagePullBackOff проверьте доступ worker к реестру.

Критерий приёмки проверяется в подготовленном стенде.

```bash
kubectl -n "$namespace" logs job/check | grep -Fx completed
```

[Условия, команды и разбор задачи](../labs/expert/k8s-job.md)

### Как решить задачу «Сопоставление Service и Pod» на стенде?

Создайте Deployment и Service, затем проверьте привязанный EndpointSlice. Service соответствует метке Deployment и получает готовую конечную точку. Если Pod уже готов, подождите синхронизации контроллера EndpointSlice.

Критерий приёмки проверяется в подготовленном стенде.

```bash
kubectl -n "$namespace" get endpointslice -l kubernetes.io/service-name=web -o jsonpath='{.items[*].endpoints[*].conditions.ready}' | grep -w true
```

[Условия, команды и разбор задачи](../labs/expert/k8s-service-routing.md)

### Как решить задачу «Сравнение разрешений учётной записи» на стенде?

Назначьте ServiceAccount чтение Pod в выделенном namespace и сравните с удалением. get разрешён, delete запрещён. При Forbidden нужна учебная роль для impersonation.

Критерий приёмки проверяется в подготовленном стенде.

```bash
kubectl -n "$namespace" auth can-i get pods --as="system:serviceaccount:$namespace:reader" && ! kubectl -n "$namespace" auth can-i delete pods --as="system:serviceaccount:$namespace:reader"
```

[Условия, команды и разбор задачи](../labs/expert/k8s-rbac.md)

### Как решить задачу «Форматирование HCL» на стенде?

Запишите неформатированный локальный файл, проверьте diff и исправьте. Первая команда меняет выравнивание, проверка возвращает 0. При ошибке парсинга проверьте кавычки и баланс скобок.

Критерий приёмки проверяется в подготовленном стенде.

```bash
terraform fmt -check -diff
```

[Условия, команды и разбор задачи](../labs/expert/terraform-format.md)

### Как решить задачу «План встроенного ресурса» на стенде?

Создайте план для terraform_data без облачных учётных данных и найдите действие create. План добавляет один ресурс. Команда apply не нужна. Если есть старый state, используйте свежий каталог.

Критерий приёмки проверяется в подготовленном стенде.

```bash
terraform show -no-color lab.plan | grep -F '1 to add, 0 to change, 0 to destroy'
```

[Условия, команды и разбор задачи](../labs/expert/terraform-plan.md)

### Как решить задачу «Контроль целостности артефакта» на стенде?

Имитируйте передачу неизменяемого артефакта между двумя шагами CI. Шаг deploy принимает совпадающий хеш. Проверка доверяет самому манифесту. Защитите его происхождение.

Критерий приёмки проверяется в подготовленном стенде.

```bash
(cd deploy && sha256sum -c SHA256SUMS)
```

[Условия, команды и разбор задачи](../labs/expert/ci-artifact.md)

### Как решить задачу «Подтверждение жизнеспособности резервного узла» на стенде?

Сымитируйте выбор обслуживающего узла при недоступном первом адресе. Выбран резервный узел secondary. Убедитесь, что 18101 не занят, а 18102 слушает процесс лаборатории.

Критерий приёмки проверяется в подготовленном стенде.

```bash
grep -Fx secondary result
```

[Условия, команды и разбор задачи](../labs/expert/ha-health.md)

### Как решить задачу «Разложение RTO по этапам» на стенде?

Сложите длительности обнаружения, переключения и прогрева в учебной выборке. Итого 40 секунд. Цель в 30 секунд не достигнута. Не складывайте параллельные этапы: используйте критический путь.

Критерий приёмки проверяется в подготовленном стенде.

```bash
test "$(cat rto)" -eq 40
```
